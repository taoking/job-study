## 优先级

1. **P0：项目表达和真实证据**。优先整理 BI 指标库、交叉表/报表、动态查询和数据平台的复杂问题、本人职责、架构取舍、前后对比数据。
2. **P0：MySQL / Redis / MQ**。练习 SQL 执行计划、缓存一致性、消息可靠性和事故排查，做到可以回答追问。
3. **P0：Spring 事务 / Java 并发 JVM，或 PHP 运行时 / Laravel**。根据具体职位选择主线，避免同一周两边都浅尝辄止。
4. **P1：系统设计、容器部署、可观测性**。以项目真实瓶颈和容量约束展开，不编造高 QPS。
5. **P2：算法与非目标技术栈**。保持基础手感，不挤占核心面试准备时间。

## 学习完成标准

一个知识点只有满足以下条件才标记为「会」：
- **讲得清**：2 分钟讲原理、条件和版本边界；
- **做得出**：用最小代码、SQL、日志或图验证；
- **能取舍**：能比较至少两种方案，说明失败模式；
- **有证据**：能关联真实工作案例（没有则如实说明是演练）。

建议每次学习写下「问题 → 结论 → 证据 → 追问 → 下次复习日」，每周复盘一次。敏感项目数据用区间或脱敏值；没有测量的数字写「待核实」，不写成个人业绩。

## 仓库维护约定

- 原有 7 天计划是**专项速览**，不是必须在 7 天内完全掌握的承诺。
- 新增主题优先写在对应专题，避免把重复面试题堆到单个大文件。
- 区分 JDK 8 / 17 / 21、Spring Framework 5 / 6、Spring Boot 2 / 3 等版本差异；优先查官方文档验证。
- 实战示例记录运行环境、复现步骤、观察结果及局限。
